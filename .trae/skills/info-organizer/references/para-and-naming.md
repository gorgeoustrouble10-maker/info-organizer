# PARA 四桶结构与命名规范

知识库按 Tiago Forte 的 PARA 方法组织，工作区 `knowledge/` 下分四桶 + 日记。

## 四桶定义

| 桶 | 路径 | 放什么 | 何时移走 |
|---|---|---|---|
| **Projects** | `knowledge/projects/` | 有明确目标/截止日的进行中工作 | 完成→移入 archives |
| **Areas** | `knowledge/areas/` | 持续职责，无截止日（人、部门、长期职责） | 长期留存 |
| **Resources** | `knowledge/resources/` | 参考材料、兴趣主题、通用知识 | 长期留存 |
| **Archives** | `knowledge/archives/` | 以上三桶中已失效的项 | 保留不删 |

日记单独放：`knowledge/daily/YYYY-MM-DD.md`，记录事件时间线（"when"层）。

## 实体文件夹结构

每个实体（一个项目/一个人/一个主题）一个文件夹：

```
knowledge/projects/<实体>/
├── summary.md    # 快速上下文，先载入（≤200字概览 + 关键事实索引）
├── items.yaml    # 原子事实列表，按需载入
└── <卡片>.md     # 该实体下的知识卡片
```

- `summary.md`：先载入，提供快速上下文；每周从活跃事实重写。
- `items.yaml`：原子事实，每条独立、带 `status` 字段；按需载入避免上下文膨胀。

## items.yaml 格式

```yaml
- id: fact-001
  fact: <一句话事实>
  date: 2026-10-09
  status: active          # active | superseded
  superseded_by: <可选>
  source_card: <对应知识卡片路径>
```

## 实体创建建议阈值（建议性，非强制）

满足任一**建议**为实体建独立文件夹；不满足则先记入日记：
- 被提及 3+ 次；
- 与用户有直接关系（同事、合作方、负责的项目）；
- 是重要项目/公司/长期职责。

> 这是建议而非铁律：高频但琐碎的事项可继续用日记 + 台账承载，无需建实体文件夹，避免目录碎片化。

## 命名规范

文件/卡片统一命名：`YYYYMMDD_部门_文档类型_v版本`

| 要素 | 规则 | 示例 |
|---|---|---|
| 日期 | 信息发生日期，YYYYMMDD | 20261009 |
| 部门 | 来源部门简称 | 行政部 |
| 文档类型 | 与五维 type 对应 | 会议纪要 |
| 版本 | v1, v2... 更替递增 | v1 |

完整示例：`20261009_行政部_会议纪要_v1.md`

### 命名好处
- 按日期自然排序；
- Glob 模式检索：`Glob pattern: "*_行政部_会议纪要_*"` 可秒级定位某部门某类全部文件；
- 版本号支持更替追踪。

## 入桶决策

> **type 不决定入桶**：type 字段表"信息性质"（如医嘱/合同/通知公告），桶归属按下表决策定。一张"医嘱"卡可入 projects（有截止）或 areas（长期职责），type 始终是医嘱。

整理一份信息时，按以下顺序判断入哪个桶：

1. 有目标/截止日且进行中？→ **projects**
2. 是持续职责（人/部门/长期）？→ **areas**
3. 是参考材料/通用知识？→ **resources**
4. 上面三桶里已失效的？→ **archives**
5. 只是当日事件流水？→ **daily**

不确定时默认 **resources**，周度复盘再调整桶位。
